Checkpoint: `runs/drivesight_v2/v2_baseline/weights/best.pt` (epoch 91, fitness/mAP50-95=0.288).
Evaluated at imgsz=1152, same validation split/settings as V1. No training launched, no
checkpoint modified. Commands and raw outputs: `reports/drivesight_v2/evaluation/`.

| model | precision | recall | mAP50 | mAP50-95 |
|---|---:|---:|---:|---:|

V2 beats both V1 variants on every global metric. Recall — the project's central pain

## 5. Visual error analysis — pedestrian/rider/motorcycle/bicycle

Ran the FP/FN/confusion audit (`audit_validation_errors.py`, conf=0.25, iou=0.70,
match-iou=0.50) at imgsz=1152 for all three models, plus GT-vs-prediction grids on the
same 6 representative images used throughout this project
(`evaluation/visual_comparison/`).

**A genuine fix, confirmed visually**: the clear daylight cyclist
(`4c1d2408-79034cda.jpg`) that V1-oversampling confidently mislabeled "pedestrian
0.68-0.72" is now correctly detected by V2 as **`rider 0.77` + `bicycle 0.59`**
(`evaluation/visual_comparison/4c1d2408-79034cda/zoom_grid.jpg`).

**A genuine, unresolved weakness**: the large, unoccluded rear-view motorcyclist
(`c96e0b6a-f3d8aa78.jpg`) is **still misclassified as `pedestrian`** by V2, exactly as
it was by both V1 variants. More training data and a cleaner pipeline did not fix this
specific viewpoint failure — consistent with the earlier diagnosis that this is a
representation/viewpoint limitation, not a data-volume problem.

**An important nuance the headline AP50 numbers hide** (`error_audit/comparison_*.csv`,
single fixed operating point conf=0.25):

| class | audit-recall v1_baseline | v1_oversampling | v2_baseline |
|---|---:|---:|---:|
| rider | 25.4% | **30.5%** | 28.8% |
| motorcycle | 26.7% | **33.3%** | 28.9% |
| bicycle | 23.0% | **37.8%** | 31.1% |

At this specific confidence threshold, **V1-oversampling still has the best raw
match-rate on all three VRU priority classes** — V2's AP50 superiority comes from
being better *across the full confidence range*, not necessarily at this exact
operating point. rider→pedestrian confusions also ticked up slightly (6→9→**10**,
baseline→oversampling→v2) — the rider/pedestrian boundary issue has not improved,
and is directly visible in the still-unfixed motorcyclist case above.

## 6. V1 comparison

Done inline above (sections 1-3, 5). Summary: V2 is a clear, broad win on
threshold-integrated metrics (AP50, mAP50-95, overall P/R) with zero per-class
regressions, but is not a uniform win at every fixed operating point, and does not
resolve the specific rider/pedestrian viewpoint confusion.

## Improvements

- Every one of the 9 classes improved in AP50, with no regressions — a clean result
  from just fixing known V1 config bugs (imgsz=1152, batch=4, explicit AdamW,
  letting training actually plateau at epoch 91 instead of a fixed 30-epoch cutoff).
- Recall (the project's headline problem) up +5.7-5.9pt over both V1 variants.
- Rider/motorcycle/bicycle AP50 all beat V1-oversampling *and* avoid oversampling's
  documented side effects (co-occurring-class inflation, the specific cyclist
  regression it introduced — now fixed).

## Regressions / weaknesses

- Bicycle small-object AR regressed vs v1_oversampling (21.7%→10.6%) despite bicycle's
  AP50 improving overall — the gain is not size-uniform.
- At a fixed conf=0.25 operating point, V1-oversampling still has the best raw
  recall on rider/motorcycle/bicycle specifically — V2's advantage is in the
  full-curve AP, not this one threshold.
- The rear-view-motorcyclist→pedestrian misclassification is unresolved, and
  rider→pedestrian confusions ticked up slightly rather than improving.

## Recommendations

1. **Recalibrate the deployment confidence threshold for V2** per-class (or overall)
   rather than assuming conf=0.25 — the audit-recall gap above suggests V2's curve
   shape differs from V1's, and a different operating point may suit it better.
2. The already-approved next experiments (`cls_pw`, `mixup` ablations) are
   well-targeted at exactly this residual rider/motorcycle/bicycle weakness.
3. The rear-view-motorcyclist viewpoint failure looks data-volume-independent;
   worth a dedicated look (e.g. targeted hard-example collection for this viewpoint)
   separately from the current ablation plan, as a candidate future-work item.
4. Re-run the full error-audit/visual-comparison pass on whichever checkpoint is
   selected after the `cls_pw`/`mixup` ablations, to see whether either closes the
   fixed-threshold VRU gap identified here.
